# 🌱 邻里童物交换日 —— 社区亲子旧物交换活动报名撮合与现场核销平台

面向社区亲子旧物交换活动的一体化单页应用：**家长报名 → 社区审核 → 智能撮合 → 预约摊位 → 带到现场 → 扫码核销 → 交换成功 / 无人交换 → 转捐或带回**，
每一件物品全程可追踪；缺席、照片不符、孩子反悔、价值争议、公益机构接收能力不足等异常，由社区、志愿者、家长、公益机构围绕同一件物品协同处理。

技术栈：**Vue 3 + TypeScript + Pinia + Vite**，纯前端实现，数据通过浏览器 `localStorage` 持久化，无需后端即可完整体验业务流程。

---

## 一、本地启动

环境要求：Node.js ≥ 18（开发验证使用 Node 22）。

```bash
npm install        # 安装依赖
npm run dev        # 启动开发服务器，默认 http://localhost:5173
```

其他命令：

```bash
npm run build      # 类型检查（vue-tsc）+ 生产构建，产物在 dist/
npm run preview    # 预览生产构建
npm run typecheck  # 仅执行 TypeScript 类型检查
```

> 若 npm 全局缓存目录有权限问题，可指定临时缓存：`npm install --cache /tmp/npm-cache`。

## 三、页面与业务流程

### 1. 家长报名 / 我的物品
报名需填写：家长称呼与手机、孩子小名与**年龄**（自动归入 0–2 / 3–5 / 6–8 / 9–12 岁段）、
物品类型（限玩具、绘本图书、衣物、学习用品、婴童用品五大类）、名称与描述、**成色照片**（可上传本地图片或填写照片说明）、
成色、**是否已消毒**、估值（自动归入价值区间）、**期望换取类型**、**可到场时间**（上/下午场多选）、
**无人交换时是否接受公益捐赠**。
「我的物品」按卡片展示每件物品的当前状态与核销码，点击可查看全流程时间线与多方留言；被驳回的物品可直接修改后重新提交。

### 2. 社区审核台
- 五大可交换品类各自的审核要点速查（如玩具查尖锐边角/小零件、婴童用品查使用期限与消毒）。
- 通过：物品进入撮合池；驳回：必须选择**危险品 / 食品 / 药品 / 隐私物品**类别并写明原因，原因对家长可见，家长修改后可重新提交。

### 3. 撮合台
按**孩子年龄段、物品类型与双方期望、价值区间、共同可到场时间**实时计算推荐组合并给出匹配度评分与推荐理由，
同时校验**目标摊位在对应入场时段的剩余容量**。社区发起邀约后，双方家长分别接受/婉拒；
双方接受后物品变为「已预约」，生成**入场时间 + 摊位提示**（如「上午场 09:00–10:30 · A 区玩具绘本摊」）。
未匹配物品可单件或批量转入 **D 区自由交换区**。

### 4. 现场核销
- 志愿者输入/扫描物品**核销码**（如 `SWAP-2026-011`）确认物品到场；
- 三项核验：**照片与实物一致、有无破损、是否已完成消毒**，全部通过才核销放行；任一不通过自动开立异常单；
- 核销通过后可确认「交换成功」（撮合配对或自由交换区配对）、标记「无人交换」、登记「孩子反悔」「价值争议」；
- 无人交换的物品按家长意愿**转捐**（选择公益机构，实时显示机构剩余接收能力）或**家长带回**；
- 五类异常均有处置入口：家长临时缺席（确认缺席）、照片不符/破损、孩子反悔、价值争议、公益接收能力不足；
  处理方式包括：补齐核验后继续交换、转自由交换区、转捐、带回、确认缺席、继续协商暂挂。
- 每件物品详情内有**多方协同留言**，社区、志愿者、家长、公益机构围绕同一物品沟通，全部留痕进时间线。

### 5. 活动总览
不是报名列表，而是**物品全流程看板**：已提交 → 审核通过 → 已预约/自由区 → 已到场 → 核销通过 → 交换成功主链，
以及已驳回、异常处理中、无人交换、已转捐、已带回、未到场等分支终态；附 KPI、摊位在场数、最近动态与品类分布。

### 6. 活动复盘
- **交换成功率**（交换成功 / 已到场）、报名与到场数、转捐数、异常争议单数；
- **未到场名单**（家庭、联系方式、原预约时段、缺席说明）；
- **捐赠去向**（按公益机构汇总接收件数/容量、物品清单、联系人）；
- **争议处理记录**（异常类型、开单人、处理结果、协同留言摘要）；
- **下一场品类缺口**：由本场家长「期望换取」需求与实际供给计算需求热度，输出供需对照表与下一场重点征集建议。

## 四、物品状态机

```
submitted ──通过──▶ approved ──双方接受邀约──▶ scheduled ──扫码──▶ arrived ──三项核验通过──▶ checked ──▶ exchanged
   │                  └──未匹配/婉拒──▶ free ──扫码──▶ arrived ...（自由交换区现场配对同样进入 exchanged）
   └──驳回──▶ rejected ──家长修改重提──▶ submitted
arrived/checked/free ──异常（缺席/不符/反悔/争议/公益满）──▶ exception ──处置──▶ checked/free/donated/brought_back/no_show
checked/free ──无人问津──▶ unexchanged ──▶ donated（转捐）或 brought_back（带回）
```

所有状态流转都会写入物品 `timeline`，异常与留言写入 `exception` / `notes`，复盘页直接汇总这些留痕数据。

## 五、推荐的手工验证路径

1. 用 `staff` 登录 → 审核台：通过「音乐叠叠乐」，把「剩余儿童感冒药」以**药品**驳回（原因自动带出可编辑），在下方"已驳回"区核对驳回类别与原因。
2. 切到 `parent` 账号：在"家长报名"页提交一件自己的物品（家长称呼默认"周妈妈"），随后在撮合台可见其进入推荐；
   "驳回后修改重提"的家长侧入口，可先由 staff 在审核台驳回一件"周妈妈"名下的报名物品，再切回 parent 体验（自动化冒烟测试也覆盖了该路径）。
3. 撮合台：可见「绘本套装 ⇄ 木质积木」「冲锋衣 ⇔ 学习机」推荐组合与容量占用 → 发起邀约 → 分别点 A/B 双方「接受」→ 生成入场时间与摊位票。
4. 用 `volunteer` 登录 → 现场核销：输入 `SWAP-2026-011` 扫码签到 → 三项核验通过 → 交换成功；
   打开种子中已在异常区的「遥控赛车」，在协同处理里选择"转入自由交换区/转捐"并写协商结论。
5. 在「无人交换」区把「校服外套」转捐给阳光儿童之家，观察机构剩余接收能力递减；容量不足时转捐会自动开"公益接收能力不足"异常单。
6. 用 `charity` 登录查看本机构接收清单；用 `staff` 打开「活动复盘」核对成功率、未到场名单（邓女士家）、捐赠去向、争议记录与下一场品类缺口。
7. 顶栏「重置演示数据」可还原全部种子状态。

## 七、目录结构

```
src/
├── main.ts / App.vue          # 入口与整体布局（侧边导航 + 顶栏 + 全局物品详情抽屉）
├── types.ts                   # 领域模型：物品、状态、异常单、邀约、时段/摊位/公益机构
├── constants.ts               # 品类/成色/价值/时段/摊位/公益机构字典与状态配色
├── labels.ts                  # 角色、异常类型、处置方式中文案
├── matching.ts                # 撮合推荐算法（年龄/品类/价值/期望/时间/摊位容量）
├── seed.ts                    # 覆盖全流程节点的演示种子数据
├── stores/
│   ├── session.ts             # 登录账号与角色会话
│   ├── data.ts                # 物品状态机、撮合、核销、异常、转捐、复盘统计（localStorage 持久化）
│   └── ui.ts                  # 跨页面物品详情抽屉
├── components/                # 物品卡片、状态徽标、生命周期流程条、模态框、物品详情
└── pages/                     # 登录 / 总览 / 报名 / 审核 / 撮合 / 现场核销 / 复盘
```
